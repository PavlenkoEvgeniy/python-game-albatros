# Design

## Context

Проект создаётся с нуля: каталог пуст, OpenSpec инициализирован, требований в коде нет. На
машине проверены Python 3.14.4, `uv` 0.13 и `pygame-ce` 2.5.8 (SDL 2.32.10, Python 3.14).
Поведение описано в `proposal.md` и дельтах `specs/*`. Ключевое ограничение — физика и счёт
должны быть проверяемы без окна и не зависеть от FPS, а вся графика и звук — генерироваться кодом.

## Goals / Non-Goals

**Goals:**

- Детерминированная симуляция полёта с фиксированным шагом, пригодная для property-тестов.
- Чёткая граница «домен ↔ pygame»: домен не импортирует pygame и не знает о пикселях.
- Стабильные 60 FPS на 1280×720 при полностью процедурной сцене.
- Централизованные параметры игры, чтобы настраивать ощущения без правок логики.
- Сборка и запуск одной командой через `uv`; CI без GPU и аудиоустройства.

**Non-Goals:**

- Реалистичная аэродинамика, термики и динамическое парение.
- Препятствия, бонусы, враги, уровни, прогрессия.
- Внешний арт-пайплайн, загрузка ассетов, редактор уровней.
- Геймпад, тач, мобильные сборки, сетевой мультиплеер.
- Настройки громкости/разрешения в UI; только горячие клавиши из спек.
- Код-подпись и нотаризация артефактов: нужны платные сертификаты Apple/Windows, поэтому
  первая версия поставляет неподписанные сборки с предупреждением ОС.

## Decisions

### 1. Стек: Python 3.12+, pygame-ce, uv

`pygame-ce` выбран вместо upstream `pygame` (активнее развивается, тот же API, колёса под
Python 3.14), вместо `arcade` (тяжелее, выше порог контроля рендера и ввода) и `pyglet`
(меньше готовых решений для HUD и шрифтов). `uv` даёт lock-файл, быстрые воспроизводимые
установки и единый запуск `uv run albatross`.

### 2. Слои и направление зависимостей

```
src/albatross/
  domain/          # чистая логика: полёт, сессия, счёт — без pygame
  application/     # GameApp: связывает домен, ввод, рендер, звук, хранилище
  presentation/    # рендер сцены и HUD, камера, локализация, звук
  infrastructure/  # путь данных, чтение/запись рекорда
  __main__.py      # точка входа, консольный скрипт
```

`domain` зависит только от стандартной библиотеки. `presentation` может читать состояние
домена, но не менять его напрямую: изменения идут через команды `GameSession`
(`request_flap`, `toggle_pause`, `restart`, `advance`). Это позволяет тестировать механику и
локализацию без SDL и не даёт рендеру влиять на физику.

### 3. Единицы мира — метры и секунды

Симуляция хранит горизонтальную координату и высоту в метрах, скорость — в м/с. Рендер
переводит мир в пиксели через `pixels_per_meter`. Дистанция в метрах — это координата `x`, а
не отдельный счётчик, поэтому расхождений между физикой и HUD нет. Масштаб подбирается так,
чтобы стартовая высота и скорость давали читаемую сцену.

Стартовые параметры (уточняются плейтестом, вынесены в `domain/config.py`):

| Параметр | Значение | Назначение |
|---|---|---|
| `START_ALTITUDE_M` | 50 | старт над землёй, земля видна в первом кадре |
| `HORIZONTAL_SPEED_MPS` | 24 | постоянная скорость вперёд |
| `GLIDE_ACCEL_MPS2` | 3,0 | приближение к скорости планирования |
| `GLIDE_SINK_MPS` | 2,2 | предельная скорость снижения |
| `FLAP_UP_SPEED_MPS` | 12 | импульс вверх при взмахе |
| `FLAP_COOLDOWN_S` | 0,25 | пауза между взмахами |
| `STAMINA_MAX` | 100 | полная полоска |
| `FLAP_STAMINA_COST` | 20 | пять взмахов за забег |
| `METERS_TO_PIXELS` | 8 | масштаб мира на экране |

### 4. Модель вертикального движения

Планирование моделируется релаксацией вертикальной скорости к `GLIDE_SINK_MPS` с ускорением
`GLIDE_ACCEL_MPS2`; снижение не разгоняется бесконечно. Взмах мгновенно задаёт вертикальную
скорость `-FLAP_UP_SPEED_MPS` (вверх), после чего та же релаксация плавно возвращает птицу к
планированию. Горизонтальная скорость постоянна.

Альтернатива — силы тяжести, подъёмной силы и сопротивления — отклонена: требует подбора
нескольких коэффициентов, хуже предсказуема в тестах и не добавляет игроку ничего, кроме
нестабильности. Модель релаксации даёт монотонное планирование и явный, легко проверяемый
инвариант «вертикальная скорость стремится к пределу снижения».

Земля — горизонтальная линия на высоте 0. Птица считается коснувшейся земли, когда её высота
становится меньше или равна нулю; забег завершается в том же шаге.

### 5. Фиксированный шаг симуляции

Симуляция идёт шагами `1/120 с`; реальное время накапливается и переводится в целое число
шагов, остаток переносится на следующий кадр. Длинный кадр (перетаскивание окна, отладчик)
ограничивается 0,25 с, чтобы не «телепортировать» птицу. Рендер использует последнее
состояние. Альтернатива с переменным `dt` отклонена: результаты зависели бы от FPS и
усложняли property-тесты.

### 6. Состояния и ввод

`GameSession` — явная машина состояний `MENU → PLAYING ⇄ PAUSED`, `PLAYING → GAME_OVER`,
`GAME_OVER → PLAYING`. Вне `PLAYING` метод `advance` ничего не меняет. Ввод обрабатывается
событиями `KEYDOWN`/`MOUSEBUTTONDOWN` без автоповтора клавиш; пробел и ЛКМ — «взмах/старт/
рестарт» по состоянию, `R` — рестарт, `Esc` — пауза/продолжение, `L` — язык, `M` — звук.
Приоритет команд на экране проигрыша: старт нового забега, взмах не засчитывается.

Альтернатива «удерживать пробел для серии взмахов» отклонена: она превращает механику в
удержание кнопки, тогда как спека требует дискретных взмахов с ограничением частоты.

### 7. Рендер: предрасчёт статики, живая птица

Сцена 1280×720. Небо — вертикальный градиент, один раз отрисованный в поверхность. Горы —
детерминированные силуэты из сидированного RNG, отрисованные в поверхности по слоям; при
движении слои сдвигаются с разной скоростью (параллакс). Облака — несколько мягких
эллипсов на своих слоях. Птица рисуется каждый кадр полигонами: тело, голова, крылья с
фазой анимации взмаха; после принятого взмаха добавляется след из полупрозрачных штрихов.
HUD — текст и полоса сил, рисуются поверх сцены. Шрифт — встроенный шрифт pygame; при
отсутствии кириллических глифов используется системный DejaVu Sans как fallback.

Камера держит птицу на 30% ширины экрана, плавно следует за высотой и не показывает ниже
земли. Все параметры цвета и пропорций — в `presentation/theme.py`.

### 8. Сохранение рекорда

Файл `record.json` в каталоге данных (`platformdirs.user_data_dir("albatross")`), формат
`{"version": 1, "best_distance_m": <int>}`. Чтение валидирует тип, целочисленность и
неотрицательность; любая ошибка — «рекорда нет», без исключения наружу. Запись — во временный
файл в том же каталоге, `flush` + `os.fsync`, затем `os.replace`: атомарная замена. Каталог
создаётся при записи, не при запуске.

### 9. Локализация

Словари `RU` и `EN` с одинаковым набором ключей в `presentation/i18n.py`; ключи типизированы
`Literal`/`Enum`, доступ — через `Translator`. Переключение сбрасывает кэш отрисованных
текстов HUD. Тест проверяет совпадение наборов ключей и отсутствие пустых строк. `gettext` не
используется: два языка и десяток строк не оправдывают каталогов `.po`.

### 10. Процедурный звук

При старте генерируются PCM-буферы: короткий шумовой «взмах» с огибающей и зацикленный
низкочастотный ветер. `pygame.mixer.pre_init(44100, -16, 2)` до `pygame.init()`. Любая ошибка
инициализации микшера переводит звук в `NullAudioBackend`; `M` переключает mute, не трогая
инициализацию. В CI/на headless-машинах используются dummy-драйверы SDL.

### 11. Тестирование и качество

- `pytest` + `pytest-cov`, `hypothesis` для инвариантов: силы в `[0, max]`, дистанция не
  убывает, при нулевых силах взмах не меняет состояние, планирование сходится к пределу
  снижения, рестарт возвращает стартовые значения.
- Тесты сессии покрывают все переходы и приоритеты ввода; тесты хранилища — отсутствие,
  повреждение и атомарность (через `tmp_path` и подмену `os.replace`).
- Рендер-смоук с `SDL_VIDEODRIVER=dummy`: кадр строится без исключений, HUD не выходит за
  границы. Полное покрытие ветвей домена — 100%.
- `ruff` (lint + format), `mypy --strict` для `src`, `pytest` в CI на Python 3.12/3.13/3.14.
- `.github/workflows/ci.yml` проверяет качество, `.github/workflows/build.yml` собирает
  установщики и публикует релиз.

### 12. Запуск и упаковка

`pyproject.toml` (hatchling), пакет `src/albatross`, консольный скрипт `albatross`. Запуск:
`uv run albatross`; для PyInstaller есть корневой `main.py`. Dev-инструменты — в
`[dependency-groups] dev`, включая `pyinstaller`. `.gitignore` исключает `.venv`, кэши,
`dist`, `*.pyc`, `screenshots`.

### 13. PyInstaller one-file как основа всех платформ

Каждая ОС собирает `--onefile --windowed` приложение из `main.py` с `--collect-all pygame` и
`--copy-metadata albatross`: так в бандл попадают SDL, встроенный шрифт и версия пакета.
Альтернатива — zipapp/встроенный Python — отклонена: не даёт нативных установщиков и хуже
работает с SDL. PyInstaller запускается на целевой ОС в матрице CI; кросс-компиляция не
используется.

### 14. Нативные установщики, а не «просто архив»

- Linux: `.deb` и `.rpm` из одного one-file бинарника; `packaging/linux/build_packages.sh`
  собирает оба пакета и кладёт `/usr/bin/albatross`, `.desktop` и PNG-иконку hicolor.
- Windows: Inno Setup (`packaging/windows/albatross.iss`) ставит `.exe`, ярлык «Пуск»,
  деинсталлятор; Inno Setup ставится через Chocolatey на раннере.
- macOS: `.app` из PyInstaller упаковывается в `.dmg` через `hdiutil` со ссылкой на
  `/Applications`.
Альтернатива — только portable-архивы — отклонена: пользователь просил установочные файлы.

### 15. CI/CD: два workflow

`ci.yml` отвечает за качество на Python 3.12–3.14. `build.yml` — за дистрибуцию: матрица
Ubuntu/Windows/macOS, тесты на каждой ОС, PyInstaller, установщики, `upload-artifact`; на теге
`v*` отдельная job скачивает артефакты и создаёт GitHub Release с deb/rpm/exe/dmg. Права
`contents: write` только у workflow с релизом. Тег обязан совпадать с версией в `pyproject.toml`
— это проверяется шагом CI.

### 16. Иконки из собственной графики

`packaging/make_icons.py` рисует иконку сценой игры и сохраняет PNG; PNG конвертируется в ICO
и ICNS через Pillow (build-time зависимость, в runtime не входит). Готовые файлы коммитятся,
поэтому CI не зависит от генератора. Linux использует PNG, Windows — ICO, macOS — ICNS.

## Risks / Trade-offs

- **Ощущения полёта могут не понравиться с первого подбора** → все константы в одном месте,
  отдельный плейтест-чеклист, возможность быстро менять без правки логики.
- **Процедурная графика выглядит плоско** → многослойные палитры, градиенты, туман между
  слоями, анимация облаков; сравнение скриншотов до/после.
- **Встроенный шрифт pygame без кириллицы** → проверить глифы тестом; fallback на системный
  DejaVu Sans, иначе — поставляемый шрифт с открытой лицензией (осознанное исключение из
  «без ассетов»).
- **Нет аудиоустройства или видеодрайвера** → `NullAudioBackend`, dummy-драйверы в тестах,
  smoke-тест рендера без окна.
- **Атомарная запись на экзотических ФС** → `os.replace` в пределах одного каталога;
  повреждённый/частичный файл игнорируется, следующий забег перезаписывает.
- **Разные DPI и размеры экрана** → фиксированное окно 1280×720; масштабирование окна — вне
  объёма, при необходимости добавляется отдельным change.
- **Python 3.14 и колёса зависимостей** → `pygame-ce` 2.5.8 проверен; версии зафиксированы
  `uv.lock`, CI проверяет 3.12–3.14.
- **PyInstaller может не включить SDL/шрифт pygame** → `--collect-all pygame` и
  `--copy-metadata albatross`, smoke-запуск собранного бинарника с `--version` в CI.
- **Неподписанные сборки пугают Windows SmartScreen и macOS Gatekeeper** → в README описано,
  как открыть приложение; подпись и нотаризация — отдельная задача с сертификатами.
- **Linux-бинарник зависит от glibc раннера** → сборка на `ubuntu-latest` (не ancient),
  deb/rpm не содержат Python; при необходимости старый дистрибутив собирается отдельно.
- **`rpmbuild` и Inno Setup отсутствуют на раннере** → устанавливаются шагом CI
  (`apt-get install rpm`, `choco install innosetup`); локально проверяется deb и Linux-бинарник.
- **Расхождение тега и версии пакета** → шаг CI сравнивает `v<version>` из тега с
  `pyproject.toml` и падает при несовпадении.

## Migration Plan

Миграции нет: проект новый, данные пользователя отсутствуют. Откат — удалить пакет и файл
`record.json` в каталоге данных. После появления GitHub-репозитория CI начинает проверять
`ruff`, `mypy` и тесты на push/PR.

## Open Questions

Нет блокирующих. Точные значения констант (высота, скорости, стоимость взмаха) уточняются
плейтестом и не меняют спеку, пока сохраняются инварианты.
