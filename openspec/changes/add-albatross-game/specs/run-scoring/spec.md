# Spec Delta

## Purpose

Хранит лучший результат игрока: обновляет рекорд по итогам забега, переживает перезапуск игры и
устойчиво переносит отсутствующий или повреждённый файл данных.

## ADDED Requirements

### Requirement: Рекорд обновляется по итогам забега

По завершении забега система MUST сравнить его дистанцию с сохранённым лучшим результатом и
обновить рекорд, если текущая дистанция больше. Если рекорда ещё нет, первый завершённый забег
MUST стать рекордом. Более слабый результат MUST NOT уменьшать рекорд.

#### Scenario: Новый рекорд
- **WHEN** забег завершается с дистанцией больше сохранённого рекорда
- **THEN** лучший результат становится равен дистанции этого забега

#### Scenario: Первый завершённый забег
- **WHEN** сохранённого рекорда нет и первый забег завершается с любой дистанцией
- **THEN** лучший результат становится равен дистанции этого забега

#### Scenario: Результат хуже рекорда
- **WHEN** забег завершается с дистанцией меньше или равной рекорду
- **THEN** сохранённый лучший результат не меняется

### Requirement: Рекорд переживает перезапуск

Лучший результат MUST сохраняться в платформенном каталоге данных пользователя и загружаться
при следующем запуске игры. Новый запуск процесса MUST показывать тот же рекорд, что был
сохранён последним завершённым забегом.

#### Scenario: Рекорд после перезапуска
- **WHEN** игрок устанавливает рекорд, закрывает и снова открывает игру
- **THEN** загруженный лучший результат равен установленному до закрытия

#### Scenario: Рестарт внутри сессии
- **WHEN** игрок начинает новый забег после проигрыша
- **THEN** лучший результат сохраняется и доступен на новом забеге

### Requirement: Повреждённый файл рекорда не ломает игру

Если файл рекорда отсутствует, не читается или содержит некорректные данные, игра MUST
запуститься без рекорда и MUST NOT завершаться с ошибкой. Следующий завершённый забег MUST
записать корректный файл.

#### Scenario: Файл отсутствует
- **WHEN** игра запускается без файла рекорда
- **THEN** игра стартует в обычном режиме
- **AND** рекорд считается неустановленным

#### Scenario: Файл повреждён
- **WHEN** файл рекорда содержит нечисловые или отрицательные данные
- **THEN** игра стартует в обычном режиме
- **AND** повреждённые данные игнорируются
- **AND** следующий завершённый забег записывает корректный рекорд

### Requirement: Запись рекорда не теряется при сбое

Сохранение рекорда MUST быть атомарным: либо на диске остаётся прежний корректный файл, либо
полностью записанный новый. Частично записанный файл MUST NOT считаться рекордом.

#### Scenario: Прерывание записи
- **WHEN** запись нового рекорда прерывается до завершения
- **THEN** при следующем запуске загружается прежний корректный рекорд
- **AND** игра не сообщает об ошибке чтения
